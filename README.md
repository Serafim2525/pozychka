# 📦 ПозичКа — «Забув? Позич за хвилину!»

Шкільна система обміну речами між учнями. Учень бачить, у кого в школі є потрібна річ (зарядка, калькулятор, форма, книга),
надсилає запит, домовляється в чаті й отримує річ через QR-код. Після повернення учасники оцінюють одне одного,
і з цих оцінок складається «карма» — рейтинг довіри.

## Швидкий старт

Потрібен лише [Node.js](https://nodejs.org) версії 18 або новішої (рекомендовано 20+).

```bash
cd pozychka
npm install
npm start
```

Відкрийте в браузері **http://localhost:3000**.

Під час першого запуску автоматично створюється файл бази `pozychka.db` і заповнюється демо-даними.
Щоб почати з чистого аркуша, зупиніть сервер і виконайте `npm run reset`.

> Жодних хмарних сервісів, API-ключів чи Docker не потрібно — усе працює локально.

## Що вміє застосунок

1. **Реєстрація та вхід** — лише з поштою домену `@school.ua`. Паролі хешуються bcrypt, сесія зберігається в httpOnly-куці.
2. **Додавання речі** — назва, категорія, опис, місце (кабінет/поверх), термін позики, фото (необов'язково).
3. **Головна та пошук** — пошук за назвою, чіпи категорій, на сторінці «Пошук» ще й фільтр за класом і «лише вільні».
   На картці: власник, клас, місце, карма власника й кнопка «Позичити».
4. **Запит на позику** — власник підтверджує або відхиляє його в розділі «Мої запити» (Профіль → Мої запити або 🔔).
5. **Чат усередині кожної позики.** Нові повідомлення й запити показує лічильник на 🔔 та на вкладці «Профіль».
6. **QR-передача** — після підтвердження позичальник отримує QR-код (вкладка «QR» → «Мій код»).
   Власник сканує його камерою (вкладка «QR» → «Сканувати») або вводить 8-значний код вручну, і статус стає «видано».
   Для повернення генерується новий код; після його сканування статус стає «повернуто».
7. **Нагадування** — у «Моїх позиках» видно, скільки днів лишилося. Якщо термін минув, з'являється червоне попередження.
8. **Карма** — після повернення обидва учасники ставлять оцінку 1–5. Карма — це середня оцінка
   (5.0, поки відгуків немає). Кожне прострочення знімає 0.5. Якщо карма учня падає нижче 2, акаунт блокується автоматично.
9. **Профіль** — мої речі, історія позик, карма, відгуки про мене.
10. **Панель адміністратора** — статистика, список користувачів, блокування й розблокування, видалення будь-яких речей.
11. **Класний керівник** («Профіль → Мій клас») бачить учнів свого класу, їхню карму, прострочення і речі на руках.

### Статуси позики

```
requested (очікує) ──► approved (підтверджено) ──QR──► given (видано) ──QR──► returned (повернуто)
        │                     │
        └──► rejected ◄───────┘   (відхилено власником або скасовано позичальником)
```

## Архітектура

```
┌──────────────┐     ┌──────────────────────┐     HTTP/JSON     ┌────────────────────────┐     SQL      ┌──────────────┐
│ 🧑‍🎓 Користувач │ ──► │ 📱 Браузер            │ ────────────────► │ ⚙️ Express-сервер        │ ───────────► │ 🗄️ SQLite     │
│ учень,       │     │ public/: HTML + CSS  │  REST API /api/*  │ server.js: маршрути,   │ better-      │ pozychka.db  │
│ вчитель,     │     │ + JavaScript         │ ◄──────────────── │ ролі, QR, карма,       │ sqlite3      │ users, items,│
│ адмін        │     │ (html5-qrcode камера)│   cookie-сесія    │ multer → uploads/      │ ◄─────────── │ loans, ...   │
└──────────────┘     └──────────────────────┘                   └────────────────────────┘              └──────────────┘
```

**Коротко:** Користувач → Браузер → Express-сервер → SQLite.

### Таблиці бази даних

| Таблиця | Поля |
|---|---|
| `users` | id, name, class, email, password_hash, role (student/teacher/admin), karma (старт 5.0), is_blocked |
| `items` | id, owner_id, title, category (Зарядки, Канцелярія, Книги, Спорт, Інше), description, photo, location, max_days, is_available, is_deleted |
| `loans` | id, item_id, borrower_id, status, created_at, due_date, qr_code, given_at, returned_at, penalized |
| `reviews` | id, loan_id, author_id, target_id, rating 1–5, comment |
| `messages` | id, loan_id, sender_id, text, created_at, is_read |

Додаткові поля (`is_deleted`, `given_at`, `returned_at`, `penalized`, `is_read`) потрібні для «м'якого» видалення речей
(щоб історія та карма не губилися), для нагадувань, для одноразового штрафу за прострочення та для лічильника непрочитаних повідомлень.

### Основні маршрути API

| Метод і шлях | Хто | Що робить |
|---|---|---|
| `POST /api/auth/register`, `/login`, `/logout`, `GET /api/auth/me` | усі | реєстрація, вхід, вихід, поточний користувач |
| `GET /api/items?q=&category=&class=&available=1` | увійшли | пошук речей |
| `POST /api/items` (multipart), `DELETE /api/items/:id` | власник / адмін | додати або видалити річ |
| `POST /api/loans` | учень | запит на позику |
| `GET /api/loans/borrowed`, `GET /api/loans/lent`, `GET /api/loans/:id` | учасники | мої позики, запити, деталі позики (QR бачить лише позичальник) |
| `POST /api/loans/:id/approve`, `/reject`, `/cancel` | власник / позичальник | рішення за запитом |
| `POST /api/qr/scan` | власник речі | видача або повернення за кодом |
| `GET`/`POST /api/loans/:id/messages` | учасники | чат |
| `POST /api/loans/:id/review` | учасники | оцінка після повернення |
| `GET /api/notifications` | увійшли | лічильники для значків |
| `GET /api/profile`, `GET /api/users/:id` | увійшли | профіль |
| `GET /api/teacher/class` | вчитель, адмін | активність класу |
| `GET /api/admin/users`, `POST /api/admin/users/:id/block`, `GET /api/admin/items` | адмін | панель адміністратора |

## Безпека

- **Паролі** хешуються bcrypt; у відповідях API хеш ніколи не повертається.
- **Сесії** через express-session: кука `httpOnly` + `SameSite=Lax`. Після входу створюється нова сесія, що захищає від фіксації сесії.
  Для HTTPS задайте `COOKIE_SECURE=1`, а в продакшені ще й `SESSION_SECRET`.
- **Ролі** перевіряються на сервері для кожного захищеного маршруту. Заблокованого користувача сервер розлогінює при наступному ж запиті.
- **SQL-ін'єкції:** усі запити до бази параметризовані.
- **XSS:** на фронтенді весь текст користувача екранується. Додатково заголовок Content-Security-Policy забороняє inline-скрипти.
- **Фото:** дозволені лише JPG/PNG/WEBP/GIF до 2 МБ. Тип перевіряється і за MIME, і за «магічними байтами» файлу, а ім'я файлу генерується випадково.
- Заголовки `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, обмеження розміру JSON-запитів.

## Камера та QR на телефоні

Браузери дають доступ до камери лише на `https://` або на `localhost`. На комп'ютері все працює за адресою `http://localhost:3000`.
Щоб сканувати телефоном у шкільній мережі, запустіть сервер за HTTPS (наприклад, через реверс-проксі).
Можна й просто ввести 8-значний код під QR-кодом вручну — це працює всюди.

## Обмеження прототипу

- Сесії зберігаються в пам'яті, тож після перезапуску сервера треба увійти знову.
- Сповіщення оновлюються опитуванням сервера (кожні 15 с, а в чаті — кожні 4 с), без push-повідомлень.
- Якщо адміністратор розблокує учня з кармою нижче 2, той лишиться розблокованим, доки не отримає нову оцінку чи штраф.
